Start with the actual upload limit

200KB allows more bytes than 50KB or 100KB, but quality depends on image detail. Use the largest permitted target, inspect the result, and keep the original if resizing removes needed text or detail.

Closed-loop compression

We encode, measure the real bytes, and retry at adjusted settings toward 200KB within configured limits. The tool reports a missed target; it cannot judge visual usability. Inspect the result.

Output is JPG

Recompressed images use JPG and transparent areas become white. If recompression would grow the file, we return the original in its original format. Check the downloaded format and dimensions.

Never a bigger file

A JPG already within the target is returned unchanged. For any accepted format, if recompression would grow the file, we return the original unchanged with a warning.

Frequently asked questions

Can every image reach 200KB?

Not every image can. The algorithm tries a bounded set of JPG quality and size settings. If the target is missed, the result includes a warning. The tool does not judge readability or photo eligibility; inspect the downloaded image yourself.

What quality will I get?

We search the configured JPG quality range for settings under 200KB, downscaling dimensions only when necessary (output is capped at 2400 pixels wide; check the destination's required dimensions and format).

Which input formats work?

JPG, PNG, WebP, and iPhone HEIC photos. Recompressed results use JPG. If recompression would grow the file, the original format is returned unchanged; check the warning and actual size.

Does compressing change my original file?

Never. Your original stays untouched on your device. The tool sends back a new, smaller copy as a download, so a bad result costs you nothing.

Why is my compressed image exactly a JPG?

The compression path encodes JPG toward 200KB. Some originals are returned unchanged, including non-JPG files when recompression would grow them. Always check the destination format rules and downloaded file.
